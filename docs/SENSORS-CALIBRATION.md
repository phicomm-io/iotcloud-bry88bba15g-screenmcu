# 原厂温湿度补偿与校准实现

2026-11-09。目标 SWM34SVET6-50；依据 SENSOR3_MCU SV.04.00.04.00，SHA256 `1d0b848af6195b39849260a3c9ff2a020d574ca9b98c2c2665d2278f349796c2`。温湿度补偿与校准执行器已接入板级配置、I²C/UART 和原厂 JSON owner。

## 温湿度

`src/sht_compensation.c` 对应原厂 `0x18268..0x18e04`。配置映射：

| C 字段 | 原厂 config 偏移 | 类型 |
|---|---|---|
| temperature | +4 | int16，十分位补偿量 |
| secondary | +6 | int16，第二补偿量，实际板级用途不臆测 |
| hcho_heat | +8 | int16，HCHO 状态关联的补偿量 |
| humidity | +10 | int16，湿度偏移，仅原厂简化分支使用 |

必须从校验后的实际板级配置加载，不能用假定的出厂系数。调用 `screen_runtime_sensor_config()` 后，`screen_runtime_sht()` 才接收样本并更新显示模型；温湿度最终值为原厂十分位整数/10。校验失败不推进补偿状态，不覆盖旧样本；旧样本仍受既有有效期约束。

- CRC8 初始 0xff、多项式 0x31；CRC 或 I²C 失败不能推进样本数。
- 原始温度 `float32(175*rawT/65534 - 45)`，原始湿度单精度 `100*rawRH/65534`；保留原厂 double/float 舍入点。
- 时间基准是**成功样本数 ×2.06**，不是系统运行秒数。大于 4200 置 settled（保持置位）；渐变模式下 `<=480` 清零两个补偿状态。
- 基础目标 `temperature+secondary`，步长为目标/3720×2.06；HCHO 关联步长为 hcho_heat/480×2.06。状态 0x59 时按原厂逻辑回归零，其余状态趋近 hcho_heat。方向比较基于绝对值，不能改成通用线性插值。
- 最终温度从原始十分位整数加两个 double 补偿后向零截断，显示限制到 -200..600。湿度重算使用**未限幅的补偿温度**，不能用显示温度代替。
- temperature 配置为 0 时，湿度为原始十分位整数+humidity，限 0..999。否则走湿度重算；此分支不再加 humidity。

湿度重算的饱和压多项式：

```
P(T) = 0.0007*T^4 + 0.0086*T^3 + 1.8046*T^2 + 41.449*T + 616.58
mix = (float32(float32(RH*622)/100) * P(rawT))
      / (10132500 - float32(RH/100)*P(rawT))
RH10 = trunc(1000 * mix*10132500 / (P(correctedT)*(mix+622)))
```

mix 为 0 时输出 0，最终限 0..999；correctedT 为未限幅十分位温度/10 后的 float32。公式说明不能替代 C 中的求值顺序。编译关闭浮点乘加合并，不能启用 fast-math。原厂恰好发生步长越界、计数回绕等行为均在正常路径保留。

`src/sensors.c` 同时修正原始湿度分母为 65534，并增加 HCHO CMD=1 最终换算及 frame[13] 原始状态读取。最低长度、LEN 和 checksum 不通过均不修改输出。未把未知的 HCHO 线上整数直接命名为 mg/m³。

## CO₂ / TVOC 校准

原厂执行器 `0x4431c` / `0x44768` 对应 `src/calibration.c`，由 `service/calibration` 的 `co2`、`tvoc` 两个字段触发。值 1 请求相应通道。重复请求拒绝，避免原厂重复请求路径的空指针缺陷。

| 传感器 | 原厂操作 | 社区接入 |
| --- | --- | --- |
| CO₂ | UART1 `11 03 03 01 90 58`，400 ppm 基准 | 连续有效读数预热 3 分钟；采样后发命令；识别 `16 01 03 E6` 应答 |
| TVOC | UART2 `11 02 03 00 EA` | 模块连续运行并有有效读数 5 分 20 秒；使用未限幅原始值采样，发出原厂命令 |
| 温湿度 | 出厂配置补偿 | 读取保留的补偿系数，不提供用户一键校准 |
| 甲醛 | `hcho_install` 仅检查 token 并应答 | 不暴露为校准 |
| PM2.5 | 未发现用户校准服务 | 保留原厂配置中的换算系数，不新增校准命令 |

执行器每 120 次轮询取样一次，共 10 个样本；极差 ≥201 拒绝。社区 BSP 每 100 ms 轮询，约 2 分钟完成采样。原厂 age 门限为 CO₂ >1597、TVOC >3195；原厂任务轮询周期尚未确定，因此这些计数不直接解释为原厂秒数。

社区 runtime 负责连续有效读数计时及结果保存。读数过期、模块休眠或升级会停止尚未发送的校准；模块恢复后重新预热。开始采样不改变传感器基准，取消仅适用于尚未发送命令的阶段。请求应答只表示接收；`command_sent` 表示 UART 接受发送；CO₂ 的 `acknowledged` 表示收到校验通过的传感器应答，需要对照参考环境复核读数。TVOC 未验证完成应答格式，保持 `command_sent`。

`data.calibration.version=1` 的快照包含 `pending`、各通道的 `ready`、`warmup_seconds`、`samples`、`state`。执行期间每 2 秒快照，空闲时保持 15 秒。取消入口为社区 `service/calibration_cancel`；原厂 JSON 命令格式保持不变。

## 校准条件与资料

- [CM1106LS 官方规格 V0.6](https://en.gassensor.com.cn/Product_files/Specifications/CM1106LS%20Single%20Beam%20NDIR%20CO2%20Sensor%20Module%20Specification.pdf) 的 UART 手动校准支持 400–1500 ppm，要求实际环境与所发基准一致，发命令前稳定至少 2 分钟。原厂 G3 固定发 400 ppm，本实现保持该值；以参考仪或标准气体确认环境，不将任意室内读数归零。G3 模块完整子型号未核实，命令与该系列协议一致。
- [AM1008L 官方产品页](https://www.gassensor.com.cn/IntegratedAirQualitySensorModule/info_itemid_1383.html) 确认其 PM/VOC 集成功能。未找到该 TVOC 校准命令的完整公开条件；前端要求洁净通风、无酒精/香水/清洁剂挥发源且读数稳定，并明确资料边界。不把 TVOC 操作描述为已验证的零点或跨度标定。

## 验证

主机测试保留原厂 CPU 输出 fixture：223 组温湿度、180 组校准单步、3 条完整双通道流程。另覆盖 CRC/截断、UART 发送失败、预热、模块停机、取消及 CO₂ 应答状态。原厂服务处理器 30 组解析后输入中，9 条空指针路径改为拒绝请求。

这些检查验证命令和状态机；传感器精度需要参考仪或标准气体实测。
